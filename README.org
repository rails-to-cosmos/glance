* Glance

*Version:* =0.7.0.1= ([[file:CHANGELOG.md][CHANGELOG.md]])

I am distilling my [[https://orgmode.org/][org-mode]] experience, habits and best practices into
this app: the project is experimental, and I will publish it once it
suits my everyday work well.

I use LLM agents in this project, mostly for prototyping, shaping and
testing (expect some sloppy tests which I'll fight eventually). I
avoid pure vibe-coding, so ownership and knowledge of the codebase
stay with me.

** Design

- Essentially an org database viewed as a keyboard-navigatable read-only table.
- UX that stood the test of time for me personally.
- [[https://webkit.org/][WebKit]] in mind from the very beginning: should run in browser and as a standalone portable application.
- Keyboard-first, familiar to emacs&vim users.
- Commands are named as elisp functions and the echo speaks them verbatim — =d= is =archive-flag=, =,= is =customize=, =q= is =quit-window= one window in.
- Sequences are org-glance's and Emacs's own: =C-c C-t=, =C-c C-s=, =C-x C-s=, =C-c C-c=, =C-c '=.
- Movement carries both dialects — =n=/=p= and =j=/=k= step rows, =f=/=b= and l=/=h= step cells, and the arrows alias both.
- dired's gestures where dired has one: =m=/=u=/=M=/=U= mark, =d= flags, =x= acts on the flagged, =D= is the quick half.
- A letter binds the *physical key*, so navigation should work for any layout if possible.

** Under it

- Org files are the single source of truth; the store, the index and every view are projections, rebuildable from the text.
- One walk into an in-memory projection, a websocket streaming each change as the file watch re-parses.
- A write replaces the exact characters a headline occupies: optimistic lock, temp-plus-rename, every other byte identical.
- Underneath, =Data.Org= — a megaparsec org grammar where every element carries a half-open character span into its document.
- Two front ends over one set of bytes: Emacs's [[https://github.com/rails-to-cosmos/org-glance][org-glance]] for editing and history, this for the table, the filter and the keyboard. Neither is authoritative; each notifies the other through =meta/EXTERNAL.jsonl=, and =make interop= runs the two against one store.

** Quickstart

#+begin_src sh
cabal run glance                            # the commands and their flags
cabal run glance -- serve   --dir ~/org     # http://127.0.0.1:7777/
cabal run glance -- desktop --dir ~/org     # same daemon, app window
cabal run glance -- repl    ~/org/todo.org  # the parser at a prompt
make native                                 # build the WebKitGTK window in
#+end_src

Flags are the program's own: a bare =glance= prints them, and =--help= follows
any command. Binds =127.0.0.1= only.

#+begin_src sh
curl -s localhost:7777/headlines | jq '.rows | length'
curl -s 'localhost:7777/headlines?q=tag:work%20sort:deadline&limit=100' | jq '.sort'
#+end_src

** Queries, by example

One string states both the narrowing and the order ([[https://github.com/rails-to-cosmos/table-view][table-view]]'s grammar,
ported term for term; divergences enumerated in [[file:AGENTS.hs][AGENTS.hs]]).

| query                           | rows served                                     |
|---------------------------------+-------------------------------------------------|
| =milk=                            | substring anywhere in the row                   |
| =state:TODO=                      | exactly that keyword                            |
| =state:TODO\vert{}DONE=           | either (alternatives OR)                        |
| =tag:work tag:home=               | both tags (tokens AND)                          |
| =-tag:work=                       | rows without the tag                            |
| =tag:*empty*=                     | untagged rows (=*word*= is a meta, never text)    |
| =state:*active*=                  | active keywords + stateless — the default view  |
| =tag:*archive*=                   | the archived rows every other query hides       |
| =-planned:*empty* sort:scheduled= | the agenda: dated rows, earliest first          |
| =ref:ROW-ID=                      | rows whose subtree links to that row (=@= drills) |
| =sort:state->title:desc=          | order by cycle, ties by title reversed          |
| =sort:*none*=                     | document order, no sort at all                  |
| =columns:State,Title,Tags=        | those columns, in that order                    |
| =view:agenda=                     | a saved view by NAME, standing for its query    |

Written order is precedence. A query naming any =sort:= replaces the default
chain (state · title · deadline · scheduled, state in the tree's own =#+TODO:=
order). =:work:= and ~=code=~ stay text: only column keys, =planned=, =ref= and
=sort= are predicates.

** Keys, the dozen that matter

The keymap is data (=Glance.Web.Keymap=): the page's last line is the whole
map. =т з о л= navigates on a Cyrillic layout.

| =n= =p= / =f= =b= | rows / cells — and in the document, siblings / grain          |
| =RET=       | materialize the row; in the document, edit the element        |
| =DEL=       | the ladder: unmark, else drop a query token, else pop a drill |
| =t= =:= =d d= =D= | state palette · tag popup · flag-then-archive                 |
| =x=         | act on the flagged, after asking · =D= is the quick one         |
| =m= =u= =M= =U=   | dired's marks                                                 |
| =o=         | follow the row's links (one opens, several list)              |
| =+=         | capture · =g= default view · =A= agenda · =P= pin into one          |
| =@=         | drill into referring rows; =DEL= walks back                     |
| =/=         | filter palette · =,= settings · =C-x C-s= sync the sheet          |

** Capture

=+= is one form: a tag field completing over the tree's vocabulary, the
template's own fields grown in place when the tag settles, the line last. =RET=
moves forward and captures; an empty tag is the inbox; =ESC= leaves it whole.
Untagged captures land in =<root>/inbox.org=, always.

A tag's template is the first heading of its config layer:

#+begin_src org
# .org-glance/config/tags/book.org
#+TODO: TODO READING | READ
* Book
:PROPERTIES:
:AUTHOR: %^{Author}
:END:
%?
#+end_src

=%?= is where the typed line lands, =%^{Author}= becomes a form field, =%U= /
=%T= stamp the server's clock; anything else copies through verbatim. A tagged
capture mints a real org-glance blob — id, shard path, =EXTERNAL.jsonl= note —
that Emacs adopts on its next refresh.

** The material document

=RET= opens the row's subtree as a document plus property panel.

- Movement is the table's two axes: =n=/=p= walk siblings at the current grain,
  =f=/=b= go a grain finer / broader (a composite's items, a headline's cells).
- A list, block or table is *one* stop, so holding =n= skims.
- Every element commits on its own (=C-x C-s= / =C-c C-c=); =RET= on a child
  drills in, =DEL= walks out.
- A moved file is a 409 the sheet waits on.
- =ORG_GLANCE_ID=, the creation stamp and =:LOGBOOK:= are server-preserved:
  never round-tripped through the client.

** Commands

=POST /command {name, id | ids, args, digests?}= — ids group by file, one
drift-locked atomic write per file, per-id answers. Refusals are 400 with
nothing written; the route never writes the store, so rows come back over the
file watch.

| name                 | args                           | writes                              |
|----------------------+--------------------------------+-------------------------------------|
| =set-state=            | ={keyword}=, nullable            | the keyword span                    |
| =set-priority=         | ={priority}=, nullable           | org's =[#A]= token                    |
| =set-title=            | ={title}=                        | the title span alone                |
| =set-planning=         | ={keyword, date}=, date nullable | one =SCHEDULED=/=DEADLINE= entry      |
| =add-tag= / =remove-tag= | ={tag}=                          | the tag on / off                    |
| =rename-tag=           | ={from, to}=                     | both ends, one write per file       |
| =archive=              | ={}=                             | =add-tag ARCHIVE=; idempotent         |
| =capture=              | ={text, tag?, fields?}=          | a headline, or a store blob         |
| =edit-link=            | ={span, target, desc?}=          | one link's own range                |
| =delete=               | ={}=                             | an archived blob, gzipped to =trash/= |

#+begin_src sh
curl -s -X POST -H 'content-type: application/json' localhost:7777/command \
     -d '{"name": "set-state", "ids": ["ROW-ID"], "args": {"keyword": "DONE"}}'
curl -s -X POST -H 'content-type: application/json' localhost:7777/command \
     -d '{"name": "capture", "args": {"text": "TODO Dune", "tag": "book",
                                      "fields": {"Author": "Herbert"}}}'
#+end_src

** Config

Org files under =<root>/.org-glance/config/=, never a row source:

#+begin_src org
# .org-glance/config/system.org — the tree-wide layer
#+TODO: TODO STARTED | DONE CANCELLED
#+GLANCE_DEFAULT_FILTER: state:*active* -tag:someday
#+GLANCE_STATE_COLORS: light TODO=#7B1FA2 DONE=#00695C
#+end_src

=tags/TAG.org= adds a per-tag cycle and a capture template. Recognition unions
every layer; classification is widest-scope (built-in > system > tags > file),
so a file redeclaring =TODO= cannot make it done-like. The settings sheet (=,=)
edits the layers and the state hues; saved views are written from the table
with =P=.

** org-glance interop

Reads and writes the same tree Emacs's org-glance does.

- Walks the canonical =data/= store; declines the derived =overviews/=, =meta/=,
  =trash/= and =occurrences/= (=--include-derived= turns that off).
- Resolves shared ids in the store's favour.
- Every daemon write into a blob appends to =meta/EXTERNAL.jsonl=; a delete
  appends the same line wearing ="tombstone":true=. =M-x
  org-glance-graph:refresh-external= folds both back.
- =glance scan= reads org-glance's index read-only and reports drift.

Details: [[file:AGENTS.hs][AGENTS.hs]] (Scan, Walk).

** Build and verify

Components: =glance-internal= (parser), public =glance= (=Glance.Query=),
=glance-web=, =glance-desktop-native=, one CLI, one suite. =glance.cabal= is
hand-maintained — no hpack.

#+begin_src sh
cabal build all                      # no GTK anywhere
cabal test                           # the suite
GLANCE_CORPUS=~/sync cabal test      # plus corpus-sampled groups (they SAY when skipped)
cabal run -v0 glance -- scan ~/sync  # the parser oracle: expect 0 span violations
make native                          # WebKitGTK window: vendored/ + GIR path, -f native-window
make sync-renderer                   # refresh assets/table-view.js from ../table-view/web
make elm                             # rebuild assets/elm.js (reproduces the committed bytes)
make elm-test                        # the scanner's own tests; fetches, so it is out of cabal test
make check-glue                      # tsc over the shell's parts
make browser                         # Chromium into ~/.cache/ms-playwright, no root
make browser-check                   # the cases a real engine measures
make interop                         # the peer, run against one store
make major | make minor | make patch # cut: bump every version site, date the changelog
#+end_src

- =frontend/= is front-end source — =glue/= for the shell, =elm/= for the two
  programs. =assets/= holds only bytes the binary embeds.
- =assets/table-view.js= and =assets/elm.js= are committed build inputs
  compiled into the binary. Neither is rebuilt by =cabal build=, so a
  source change owes its =make= step.
- =--assets ../table-view/web= serves the sibling checkout live.
- =vendored/= exists because Arch ships WebKit2 4.1 typelibs only;
  =cabal get NAME-VERSION && diff -r= shows the whole patch.
