* Glance

** Summary

*Glance* serves an org tree as a keyboard-driven table in a browser tab and
writes back into the files by span splice. Org files are the single source of
truth: the daemon walks a directory once into an in-memory projection, answers
=/headlines= out of it, streams every change over a websocket as the file watch
re-parses one file per edit, and every write replaces the exact characters a
headline occupies under an optimistic lock, temp-plus-rename, leaving every
other byte identical. Under that sits the stateful org-mode parser this project
began as — =Data.Org=, a megaparsec grammar threading a =Context=, where every
element carries a half-open character span into its document: headlines at any
level, =#+TODO:=-declared states, priorities, tags, property drawers, planning
lines, and active and inactive timestamps with ranges and repeaters.

** Quickstart

#+begin_src sh
cabal run glance -- serve   --dir ~/org     # http://127.0.0.1:7777/
cabal run glance -- desktop --dir ~/org     # the same daemon, in a window of its own
make native                                 # build the WebKitGTK window in (-f native-window)
#+end_src

=serve= takes =--dir=, =--port= (default 7777), =--assets PATH= and
=--include-derived=. =desktop= takes those plus =--browser CMD=, =--dry-run= and
=--keep-serving=; it opens =$GLANCE_BROWSER=, then =--browser=, then the first
chromium-family browser on =PATH= as ~CMD --app=URL~, then =xdg-open=, then
prints the URL, and no window failure ever takes the daemon down. A build
carrying its own window prefers it, naming a browser still beats it, and
=--dry-run= says which won.

The listener binds =127.0.0.1= and nothing else; privilege tiers arrive with S7
(=docs/plan-org-console-web.md=). It binds *before* it walks: over ~6.3k files
the walk is ~10 s, during which the store routes answer =503= with
=Retry-After: 1= and ={"loading": true, "elapsed": S}= while =/= and the assets
serve, so the shell paints an indexing state and polls out of it. Order is fixed
— bind, window, walk, watch. Nothing is installed beside the binary:
=assets/table-view.js= is compiled in, every served page fetches only from this
server, and no source file names a path outside the repository.

The HTTP surface is a fixed route table — =/=, =/headlines=, =/headline=
(GET + POST), =/command= (POST), =/config= (GET + POST), =/keywords=, =/links=,
=/tags=, =/ws=. =/headlines= answers table-view's View object with the load
counts in =X-Glance-*= headers and =ETag: "<fingerprint>-gN"= under
=Cache-Control: no-cache=, so an unchanged tree costs a 304 rather than a body.
~?limit=~ caps at 20000, bodies cap at 1 MiB, and ~?order=~ is refused with a
400 naming =sort:= as its replacement.

#+begin_src sh
curl -s localhost:7777/headlines | jq '.rows | length'
curl -s 'localhost:7777/headlines?q=state:*active*%20sort:deadline&limit=100' | jq '.sort'
#+end_src

** The surfaces

*The table is a list of entries, one row per top entry.* A level-one headline
carrying at least one of the six column cells gets a row; a deeper headline is
reached by materializing the entry it belongs to. The columns are =State=, =#=
(priority), =Title=, =Scheduled=, =Deadline= and =Tags=. Archived rows are left
out unless a query names =tag:*archive*=, and =X-Glance-Archived= counts what
was hidden. =glance scan= still counts every headline at every level — it is a
parser oracle rather than a view.

*The keymap is data, and the served page is its documentation.*
=Glance.Web.Keymap.keyBindings= is one map — no profiles, both spellings bound at once
(=n=/=j=, =f=/=l=) — carried into the page as a JSON blob that the dispatch, the
echo pill and the resident key line all read. Press a key and the pill says
=SEQ → command=; the last line of the page is the whole map's summary. Nothing
is restated here, so a binding cannot go stale in this file. A letter binding
names the *physical key* rather than the character, so a Cyrillic layout
navigates on =т з о л= and punctuation stays the character it types. Two rules
worth knowing off-page: =DEL= is a ladder (unmark all, else drop the query's last
token, else pop a drill's crumb), and =C-c C-t= is bound and correct but never
completes in a browser, =Ctrl+T= belonging to the browser process — which is
what the native window fixes and what the plain =t= works around.

*The popups*, one line each:

- =/= — the *filter palette*, the renderer's own overlay; the applied query
  rides in the URL, so a filtered view is a link.
- =t= — the *state palette*: ~GET /keywords?ids=…~ answered as a table
  (=Source= | =Active= | =Inactive=, widest layer first, =*empty*= at the foot),
  which-key, a letter commits on its own; =/= falls back to a completing-read.
- =:= — the *tag palette* over the same rows, under dired's normalize-up rule (a
  tag every row carries comes off, a tag some carry goes on), and it stays up.
- =o= / =!= — the *link popup*: a table of the row's links (kind, description,
  target) off ~GET /links?id=~; =o= opens one, =RET= edits it.
- =+=, =C-c C-s=, =C-c C-d= — a *one-line prompt*: capture text, or a date
  (=2026-08-05=, =today=, =+3d=, or org's own bracketed form kept verbatim).
- =,= — the *settings sheet*, three panels: general (default view, capture
  target, log lines), theme, keywords.

*The material document.* =RET= opens the row's subtree over the table as a
document, a property panel and a read-only logbook strip. The document is walked
as *grains*: every element is a stop, and a list, a =#+begin_…= block and an org
table each take two stops over the same bytes — the whole, then its parts —
emitted inline in document order, so =n= meets the composite and walks into it
with no descend key. Every element writes on its own, a lens splice for a
paragraph and a =/command= for the headline's own cells, so the document holds
no unsaved work; the panel and raw mode are what =dirty()= reads. =RET= on a
child drills into it (~?child=N~, document order over the whole subtree) and
=DEL= walks back out, with the sheet's own crumb strip saying where you are.
Links are span-driven rather than searched: =o= narrows to the element the
cursor is on. =C-c '= swaps to raw org by re-materializing, so an edited sheet is
refused rather than converted in a page that holds no org parser. =C-x C-s=
syncs, =C-c C-c= commits the open element, =ESC= is a ladder out, and a file that
moved underneath is a 409 the sheet waits on at =conflict=. Two things are the
server's and ride out but never back: =ORG_GLANCE_ID= plus
=ORG_GLANCE_CREATION_TIME=, and the whole =:LOGBOOK:= drawer.

*The event strip* under the table is append-only, keeps 500 lines
(=HH:MM:SS SEV scope message=, scopes =ws=/=sync=/=cmd=/=filter=/=config=/=boot=)
and names every row a write landed on and every one refused; its height is the
settings sheet's =log lines= field. There is no status corner: when a change can
no longer reach the page — a view being replaced, a socket gone — the page fades
back and the strip says why in words.

** The grammar

~?q=~ is one query stating both the narrowing and the order, and it is
[[file:../table-view/SCHEMA.md][SCHEMA.md]]'s micro-syntax ported term for term
into =Glance.Web.Filter= and =Glance.Web.Sort= — parity with =table-view.js= is
the contract, and the known divergences are enumerated in
[[file:docs/invariants.md][docs/invariants.md]]. Tokens split on whitespace and
=&=; =key:value= (~=~ is an alias) is a predicate only where =key= names a
column or one of =planned=, =ref= and =sort=, so =:work:= and ~=code=~ stay the
org text they are and an org tag is reached as =tag:course=; =-= negates a whole
token, a token opening with a quote is free text, and everything unmatched is a
case-insensitive substring of the row as it displays. *Tokens AND, alternatives
OR*: =tag:a tag:b= carries both, =state:TODO|DONE= is either. A value between
asterisks is a *meta* and a bare word never is — =key:*empty*= is the empty cell
on every key, =tag:*archive*= the whole archive tag, =state:*active*= /
=state:*inactive*= the keyword groups a tree declares, =sort:*none*= the empty
chain. =ref:ID= is every row whose subtree points at the row named, which only
the store can answer and which =@= applies as a drill. =sort:COL= orders and
narrows nothing, =sort:COL:desc= reverses, written order is precedence, and a
query naming any sort key replaces the default chain (state, title, deadline,
scheduled — state read in the tree's own =#+TODO:= order). A column named twice,
a negated or alternated sort token, an unknown column and a companion beside
=sort:*none*= are each a 400 naming the token.

** Commands

One route — =POST /command {name, id | ids, args, digests?}= — and ten names.
Ids group by file and each file is one drift-locked write, so a marked set over
three files is three atomic writes; the answer is per id
(={results: [{id, ok, digest | error}]}=) in the order the ids were named.
Request-shape refusals are 400 with nothing written; 413 outranks everything.

| name           | args                         | what it writes                              |
|----------------+------------------------------+---------------------------------------------|
| =set-state=      | ={keyword}=, nullable          | the keyword span; legality is per file      |
| =set-priority=   | ={priority}=, nullable         | org's =[#A]= token; =S-<up>= / =S-<down>= cycle it |
| =set-title=      | ={title}=                      | the title span alone                        |
| =set-planning=   | ={keyword, date}=, date nullable | one =SCHEDULED=/=DEADLINE= entry              |
| =add-tag=        | ={tag}=                        | the tag onto the headline                   |
| =remove-tag=     | ={tag}=                        | the tag off it                              |
| =rename-tag=     | ={from, to}=                   | both ends in one write per file             |
| =archive=        | ={}=                           | =add-tag= at org's own =ARCHIVE=; idempotent    |
| =capture=        | ={text}=                       | one headline at the capture target's end    |
| =edit-link=      | ={span, target, desc?}=        | one link's own range                        |

=set-title= replaces the title span alone, so the keyword, the priority and the
tags around it keep their bytes; clearing a planning entry that was the line's
last takes the line with it; =capture= is the one command naming no row and
=edit-link= the one naming exactly one.

The route never writes the store: the rows come back over the file watch a
moment later, like every other edit.

#+begin_src sh
curl -s -X POST -H 'content-type: application/json' localhost:7777/command \
     -d '{"name": "set-state", "ids": ["ROW-ID"], "args": {"keyword": "DONE"}}'
#+end_src

** Config

Configuration is org files under =<root>/.org-glance/config/=, and they are
never a row source. =system.org= is the tree-wide layer and =tags/TAG.org= is one
per tag; each carries a =#+TODO:= cycle, and =system.org= carries two lines
beside it — =#+GLANCE_DEFAULT_FILTER:= (the query =g= applies and a bare page
opens on; absent means =state:*active*=) and =#+GLANCE_CAPTURE_TARGET:= (where
=+= writes; absent means =<root>/inbox.org=, and a target outside the walk is
refused where the config is read).

Recognition unions every layer — a keyword declared anywhere parses everywhere —
while classification is nearest-scope: file > tags > system > built-in > union.
That one chain is =Config.keywordScopes=, read forwards by =classify= and per row
by =GET /keywords=, which is what the state palette draws. =GET=/=POST /config=
serve and replace one layer through the ordinary write path, so a =#+TITLE:=, a
comment and org-glance's capture template come back byte for byte; the settings
sheet (=,=) is that pair with a box per layer. Full rules in
[[file:docs/invariants.md][docs/invariants.md]] (Keyword configuration).

** org-glance interop

The daemon reads and writes the same tree Emacs's org-glance does. It walks
=.org-glance/data/= — the canonical store — and declines =overviews/=, =meta/=
and a blob's =occurrences/= history as derived renders of headlines it already
has (=--include-derived= turns that off), declines =config/= always, and resolves
a shared =ORG_GLANCE_ID= in the canonical store's favour, counting the losers in
=X-Glance-Id-Collisions=. A write into a blob appends one line to
=.org-glance/meta/EXTERNAL.jsonl= — ={"id": …, "at": …}=, append-only, never
truncated — which is how =M-x org-glance-graph:refresh-external= learns about an
edit Emacs did not make. And =glance scan= folds org-glance's write-ahead index
read-only (MANIFEST segments oldest-first, then the open =headlines.jsonl=,
latest record per id wins) and reports where the index and the blobs disagree —
a drift instrument rather than a repair. Details: =Data.Org.Walk=,
=Data.Org.External=, =Data.Org.Index=, [[file:docs/invariants.md][docs/invariants.md]] (Scan, Walk, Architecture).

** Build

=glance.cabal= is hand-maintained; hpack is gone, so do not regenerate it.
Components: private sublibrary =glance-internal= (=src/=, the parser and its
AST), the public library =glance= (=src-query/=, =Glance.Query= alone), private
=glance-web= (=src-web/=, depending on the public library and nothing else),
private =glance-desktop-native= (=src-desktop-native/=, on =base= alone), one CLI
dispatching to three of them, and one suite. The facade constraint is a solver
error rather than a review note.

#+begin_src sh
cabal build all        # the unflagged build: no GTK anywhere, and CI needs none
make test              # cabal test
make sync-renderer     # refresh assets/table-view.js from ../table-view/web
make native            # cabal.project.native + the GIR search path, -f native-window
#+end_src

=native-window= is off by default and manual, and reaches exactly one stanza, so
every other component is byte-identical either way. On, the solver pulls ~28
haskell-gi packages generated from the machine's typelibs and the build needs
GTK3 and WebKitGTK headers. =make native= rather than =cabal build -f= because
two things have to be supplied first: =vendored/= carries =gi-webkit2= and
=gi-javascriptcore4= as upstream cut them with the lines marked =glance:=
repointed at the WebKit2 *4.1* typelibs (Arch dropped the 4.0/libsoup2
generation), and =vendored/gir/= carries =cairo-1.0=, =xlib-2.0= and
=freetype2-2.0=, the hand-written GIRs that ship in =gobject-introspection= where
this machine has only =-runtime=. =cabal.project.native= names the first and
=HASKELL_GI_GIR_SEARCH_PATH= the second, which is the one thing a project file
cannot say. Both vendored packages keep upstream's name and version on purpose —
a local package shadows Hackage's — so =cabal get NAME-VERSION && diff -r= is the
whole patch. An upstream release binding 4.1 retires =vendored/=; a distribution
shipping =gobject-introspection= retires =vendored/gir/=.

** Verification

#+begin_src sh
cabal test                                          # the suite
GLANCE_CORPUS=~/sync cabal test                     # plus the corpus-sampled groups
cabal run -v0 glance -- scan ~/sync                 # the parser oracle over a real tree
#+end_src

The scan is the standing oracle: expect *0 span violations* and ~12.6k
headlines, with =walk seconds= around 10–11 warm. Measured 2026-08-03 over
=~/sync=: 6292 files, 6265 ok, 12599 headlines, 517136 elements, 0 span
violations, 9 id collisions, 10.44 s walk. It then folds org-glance's index per
store and prints the disagreement block (=~/sync/views=, same run: 6521 records
read, 6073 live, 0 malformed, 6065 blobs parsed, 21 idless, 69 rows disagree, 0
unindexed blobs, 29 records without blobs).

The =GLANCE_CORPUS= groups *pass* when the variable is unset and print
=SKIPPED — GLANCE_CORPUS is unset: <label>= on stderr for each, so a green run
without those lines answered is unverified on the corpus half. A variable naming
a directory that is not there fails loudly, and so does a run that samples
nothing.

** Hacking the renderer

The table is drawn by [[https://github.com/rails-to-cosmos/table-view][table-view]], which lives in its own repository
and is vendored here as =assets/table-view.js= — a committed build input, read
at *compile* time by a TH splice and carried in the binary.

#+begin_src sh
# 1. hack it in the sibling checkout, serving it off disk — no rebuild per edit
cabal run glance -- serve --dir ~/org --assets ../table-view/web

# 2. bring the result back, and see what moved
make sync-renderer

# 3. commit assets/table-view.js like any other file, and rebuild
git add assets/table-view.js && cabal build
#+end_src

=--assets= *replaces* the compiled-in renderer, which is what keeps the
missing-asset path reachable and makes it reachable under that flag alone; a
directory without =table-view.js= means no table, and =/headlines= keeps working.
=make sync-renderer= says so honestly when there is no sibling checkout, so a
clone of this repository alone still builds and still serves the page.
Self-containment is a rule rather than a convenience: no source file may name an
absolute path outside the repository, and =test/TestSelfContained.hs= sweeps
=src*/= and =app/= for one.
